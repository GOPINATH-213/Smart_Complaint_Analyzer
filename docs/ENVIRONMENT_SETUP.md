# Environment Setup Guide

This guide details the configurations for managing multiple environments (development vs. production) in the Smart Complaint Analyzer system.

---

## 1. Environment Organization

### Flutter Environment variables
Only client-specific environment variables are stored in the Flutter environment. Sensitive API keys (like Google Gemini and Cloudinary secrets) are handled exclusively by the Node.js backend.
* **APP_NAME**: Display name for the application.
* **APP_VERSION**: App version number.
* **APP_ENV**: Running environment mode (`development` or `production`).
* **API_BASE_URL**: Base URL of the backend API (e.g. `http://10.0.2.2:5000/api` for Android emulator).
* **ENABLE_AI**: Feature flag to toggle AI tools visibility.
* **ENABLE_ANALYTICS**: Toggle analytics dashboards.
* **ENABLE_DEBUG_LOGS**: Toggle console log printouts.

*All Firebase configurations are loaded directly from `lib/firebase_options.dart` generated by the FlutterFire CLI, and are no longer duplicated in the `.env` variables.*

### Backend Environment variables
The backend manages all secrets and third-party API configurations:
* **Server settings**: `PORT`, `NODE_ENV`, `API_VERSION`, `BASE_URL`, `CLIENT_URL`.
* **MongoDB**: `MONGODB_URI`, `DATABASE_NAME`.
* **Security & JWT**: `JWT_SECRET`, `JWT_EXPIRES_IN`, `BCRYPT_SALT_ROUNDS`.
* **Firebase Admin SDK**: `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `FIREBASE_STORAGE_BUCKET`.
* **Gemini AI**: `GEMINI_API_KEY`, `GEMINI_MODEL`.
* **Cloudinary**: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
* **Email (Brevo)**: `BREVO_API_KEY`, `BREVO_SENDER_EMAIL`, `BREVO_SENDER_NAME`.
* **Rate Limiting**: `RATE_LIMIT_WINDOW_MS`, `RATE_LIMIT_MAX_REQUESTS`.
* **Logging**: `LOG_LEVEL`.

---

## 2. Dynamic Environment Loading Setup

### Flutter App Env Loading
* Environment files are stored in the root folder: `.env.development` and `.env.production`.
* **Version Control**: Actual configurations are ignored by Git. Only `.env.example` templates are tracked.
* **Loading active configuration**: Copy your environment parameters into `assets/.env` before launching/building:
  ```bash
  # Development Launch example
  cp .env.development assets/.env && flutter run
  ```

### Backend Env Loading
* Environment files are loaded via `dotenv` from `src/config/index.js` depending on the active `NODE_ENV` configuration.
* If required variables are missing, the server performs a **fail-fast check** at startup, terminating execution immediately with a clear error trace.
